# tools/ —— 个人站里的工具

点开 `index.html` 上的卡片会跳到这里的 html。**全部是单文件、零依赖、双击即用**（不联网也能跑）。

---

## 1. 文件一览

| 文件 | 大小 | 是什么 | 能直接改吗 |
|---|---|---|---|
| `prompt-builder.html` | 224 KB | **成品** —— 用户打开的「AI 生图提示词装配台」 | ❌ **不要改**（会被构建覆盖） |

## 2. ⚠️ 为什么「提示词装配台」有两个文件

**因为它有 1965 条词库要维护**，数据不适合直接写死在代码里。

```
prompt-builder.template.html          ← 源码：界面 + 逻辑（第 241 行有个占位符）
        +
../提示词词库/*.txt   （12 个文件）    ← 词库数据
        ↓
   node _dev/build-prompt-builder.mjs ← 构建脚本（在项目根目录的 _dev/ 里）
        ↓
prompt-builder.html                   ← 成品：源码 + 打包好的词库
```

### 那个占位符长这样

**模板里**（第 241 行）：

```html
<script>/*__LEX_DATA__*/</script>
```

**构建脚本**把 12 个词库 txt 打包成 JSON，替换掉它：

```js
writeFileSync(OUT, tpl.replace(MARK, 'window.__LEX__=' + json + ';'), 'utf8');
```

**成品里**同一个位置，变成了一个约 133 KB 的数据块。

### 铁律

> **模板 + 词库 = 唯一源。成品是「产物」，永远不手改。**

```
❌ 改 prompt-builder.html  →  下次构建，你的改动被覆盖
✅ 改 prompt-builder.template.html  →  构建后改动保留
```

**改完模板必跑这一步**：

```powershell
cd 本仓库根目录
node _dev\build-prompt-builder.mjs
```

> ⚠️ **改完不构建 = 白改。** 浏览器打开的还是旧的成品。
> 这一步我漏过好几次，看页面没变化才发现。

## 3. 为什么另外两个不用拆

| | 提示词装配台 | gif-tool / img-compress |
|---|---|---|
| 数据量 | **1965 条词，要持续增删改** | 几十行配置，基本不动 |
| 维护方式 | 几乎天天在改词库 | 改一次就不动 |
| 结构 | 必须拆 | 单文件就够 |

**只因为有 1965 条要维护，才值得拆。** 别为了"看起来规范"把简单工具也拆开。

## 5. 新增一个工具怎么做

1. **单文件** → 直接写 `新工具名.html`，丢进这个文件夹
2. **需要外部数据 / 要持续维护** → 拆成 `新工具名.template.html` + 数据目录 + 构建脚本
3. **去 `index.html` 加一张卡片**（照抄现有那张的写法，改 `data-href` / `data-kw` / 标题 / 描述）
4. **打开 `index.html` 自测**：手机上（≤560px）也要看一眼

**命名规则**（见项目 `AGENTS.md`）：文件名一律**小写英文 + 连字符**，不用中文。
